# 密钥轮换手册

> 部署完成后执行。三项互相独立，可以分开做、分开验证，**不要一次全改**——
> 一次只动一项，验证通过再动下一项，出问题才知道是谁引起的。

## 一、为什么必须轮换

| 泄露内容 | 怎么泄的 | 影响 |
| --- | --- | --- |
| 数据库密码 | 曾硬编码在 `ecosystem.config.cjs` 里并提交进 Git | 拿到仓库历史的人都能读到 |
| `JWT_SECRET` | 同上 | 能伪造任意用户的登录态，**包括管理员** |
| 服务器 root 密码 | 曾以明文形式在对话中传递 | 可直接登录服务器 |

`70450f8` 已经把 PM2 配置改成从 `.env` 读取，但**Git 历史里的旧值永远删不掉**
（除非重写历史，见文末）。所以补救办法只有一个：把旧值作废。

其中 `JWT_SECRET` 最紧急——它不只是「泄露了一个密码」，而是**任何人都能凭它
伪造管理员身份**，不需要知道任何账号密码。

## 二、执行顺序

按风险从低到高做，每步都能独立验证：

1. **服务器 root 密码 + SSH 加固**（不影响业务，随时可做）
2. **数据库密码**（需重启应用，停机约 10 秒）
3. **`JWT_SECRET`**（需重启应用，**所有已登录用户被登出**，挑非上课时段）

---

## 三、准备：先单独备份 .env

`.env` 改错了服务就起不来，先留一份：

```bash
cd <项目目录>
cp .env ".env.bak.$(date +%Y%m%d_%H%M%S)"
chmod 600 .env.bak.*
ls -la .env.bak.*
```

> 全量备份包里也有 `.env`，但那是轮换**之前**的版本。这份是你改坏时最快的后路。

---

## 四、第 1 步：服务器 root 密码与 SSH 加固

```bash
# 改 root 密码（交互式输入，不要写在命令行里，否则会进 shell 历史）
passwd root
```

新密码要求：**16 位以上，大小写字母+数字+符号**。不要再用 `qwert123A` 这一类。

改完**不要断开当前 SSH 连接**，先另开一个终端验证能用新密码登录，确认后再关旧连接。
（万一改错了，旧连接还开着，还能救回来。）

验证通过后加固 SSH——这一步比换密码更管用：

```bash
# 1) 先把你本机的公钥装上（在你自己的电脑上执行）
ssh-copy-id root@121.196.217.243

# 2) 确认能免密登录后，再在服务器上关掉密码登录
sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
sshd -t && systemctl reload sshd
```

> **顺序不能反。** 没装好公钥就关密码登录，你会把自己锁在门外。
> `sshd -t` 是配置语法检查，通过了才 reload。

再把 22 端口收敛到你常用的出口 IP：阿里云控制台 → 安全组 → 入方向规则，
把 22 端口的授权对象从 `0.0.0.0/0` 改成你的固定 IP。若你的 IP 会变，
至少改成学校/单位的网段。

**验证**：新终端能用密钥登录；旧密码登录被拒绝。

---

## 五、第 2 步：数据库密码

`.env` 里的 `DATABASE_URL` 形如 `mysql://用户:密码@主机:端口/库名`。
用户名不是机密，可以单独看：

```bash
grep -oP 'mysql://\K[^:]+' .env    # 只打印用户名，不会带出密码
```

生成新密码——**只用字母和数字**，避免 `@ : / ? # &` 等字符在连接串里需要转义：

```bash
NEWPW="$(openssl rand -base64 24 | tr -dc 'A-Za-z0-9' | head -c 32)"
echo "新密码已生成，长度 ${#NEWPW}"
```

**先把它存进密码管理器再往下走**——丢了就得重来一遍：

```bash
echo "$NEWPW"        # 复制到密码管理器后，清屏：clear
```

> 只用字母数字是为了省心，不是必须：下面的改写脚本会做百分号编码
> （已用 mysql2 实测确认驱动会正确解码），所以密码含 `@ : / # ?` 也不会出错。
> 但纯字母数字在排查问题时更不容易看花眼。

改数据库和改 `.env` **必须连着做**，中间应用会连不上库：

```bash
DBUSER="$(grep -oP 'mysql://\K[^:]+' .env)"

# 先确认这个用户是按哪个主机授权的（可能不是 localhost）
mysql -u root -p -e "SELECT user, host FROM mysql.user WHERE user='${DBUSER}';"

# 1) 改数据库密码。用 heredoc 而不是 -e：
#    -e 的内容会出现在进程列表里（ps 能看到），heredoc 走标准输入不会。
#    下面的 localhost 按上一条命令查出来的 host 改。
mysql -u root -p <<SQL
ALTER USER '${DBUSER}'@'localhost' IDENTIFIED BY '${NEWPW}';
FLUSH PRIVILEGES;
SQL

# 2) 同步改 .env 里连接串的密码段（只替换密码，用户名/主机/库名原样保留）
python3 - "$NEWPW" <<'PYEOF'
import os, re, sys
from urllib.parse import quote

pw = sys.argv[1]
lines = open(".env", encoding="utf-8").read().split("\n")
hits = 0

for i, line in enumerate(lines):
    m = re.match(r"""^(\s*DATABASE_URL\s*=\s*["']?)(mysql://)([^\s"']+)(["']?\s*)$""", line)
    if not m:
        continue
    prefix, scheme, rest, suffix = m.groups()
    # 从最后一个 @ 切开：旧密码里可能就含 @，从第一个 @ 切会把主机名一起吃掉
    at = rest.rfind("@")
    assert at > 0, "DATABASE_URL 里找不到 @，格式不符合预期，已中止"
    cred, host = rest[:at], rest[at + 1:]
    colon = cred.find(":")
    assert colon > 0, "DATABASE_URL 里分不出用户名和密码，已中止"
    user = cred[:colon]
    # 百分号编码：新密码即使含特殊字符也不会破坏连接串
    lines[i] = prefix + scheme + user + ":" + quote(pw, safe="") + "@" + host + suffix
    hits += 1

assert hits == 1, "预期改写 1 行 DATABASE_URL，实际 %d 行，已中止" % hits
open(".env", "w", encoding="utf-8").write("\n".join(lines))
os.chmod(".env", 0o600)
print("DATABASE_URL 密码段已替换")
PYEOF

# 3) 重启
pm2 restart zjgsu-supervisor
unset NEWPW
```

> 两个 `assert` 是刻意的：`.env` 里有多条或零条 `DATABASE_URL`、或连接串格式不符合预期时，
> 脚本会**直接中止并保持原文件不动**，而不是改出一个半对半错的 `.env`。
> 从**最后一个** `@` 切分也是刻意的——旧密码本身就含 `@`，从第一个 `@` 切会把主机名一起吃掉，
> 得到一个看似正常、实则连不上库的连接串。

**验证**：

```bash
pm2 logs zjgsu-supervisor --lines 30      # 不应有数据库连接错误
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3000/
```

再到网页上打开任意一门课的列表，确认数据正常读出。

**回滚**：`cp .env.bak.<时间戳> .env && pm2 restart zjgsu-supervisor`，
并把数据库密码用同样的 `ALTER USER` 改回去。

## 六、第 3 步：JWT_SECRET（会让所有人重新登录）

**先通知用户**，或直接挑深夜/周末执行。轮换后所有人的登录态失效，
需要重新登录一次——不丢任何数据，但正在填写的评价草稿若未保存会丢，
所以不要在上课时段做。

```bash
NEWSECRET="$(openssl rand -hex 32)"

python3 - "$NEWSECRET" <<'PYEOF'
import os, re, sys
s = sys.argv[1]
src = open(".env", encoding="utf-8").read()
if re.search(r'^JWT_SECRET=', src, re.M):
    new, n = re.subn(r'^JWT_SECRET=.*$', "JWT_SECRET=" + s, src, flags=re.M)
    assert n == 1, f"预期替换 1 处，实际 {n} 处，已中止"
else:
    new = src.rstrip("\n") + "\nJWT_SECRET=" + s + "\n"
open(".env", "w", encoding="utf-8").write(new)
os.chmod(".env", 0o600)
print("JWT_SECRET 已更新")
PYEOF

pm2 restart zjgsu-supervisor
unset NEWSECRET
```

**验证**：

1. 用一个**已经登录**的浏览器刷新页面 → 应被踢回登录页（说明旧 Token 已失效，正是目的）
2. 重新登录 → 正常进入
3. 换一个角色的账号再登一次，确认权限正常

**回滚**：`cp .env.bak.<时间戳> .env && pm2 restart zjgsu-supervisor`
（回滚后用户又要再登一次）

## 七、收尾

- 删掉临时备份：确认一切正常后 `shred -u .env.bak.*`（`shred` 会覆写内容再删）
- **不要**把新密钥发到聊天工具、文档或邮件里。需要记录就用密码管理器。
- 全量备份包里含明文 `.env`，属机密文件，不要放共享盘、不要外传。
  轮换后旧备份包里的仍是旧密钥——那份备份依然可用（DB 与 .env 是同一时刻的、自洽的），
  但它现在也是一份「旧密钥副本」，同样要妥善保管或销毁。

## 八、关于 Git 历史

轮换之后，历史里的旧值就是一串废字符串，**通常不必重写历史**。
只有在下面这种情况才值得折腾：仓库是公开的，或曾经公开过。

如果确实要清，用 `git filter-repo` 而不是 `filter-branch`，并且注意这会改写所有
commit 哈希——**所有克隆过这个仓库的人都要重新克隆**，服务器上的部署目录也要重新拉。
在换学期刚上线的节骨眼上不建议做，等系统稳定一段时间再说。
