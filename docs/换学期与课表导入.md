# 换学期与课表导入操作手册

面向部署时执行操作的人（或 Agent）。整个过程**不删除任何历史数据**：
上学期的课表会被「归档」而不是清空，去年的评价和听课计划仍然指得到它们评的是哪门课。

---

## 一、核心概念：归档，而不是清空

`courses` 表有一列 `semesterId` 标记课程属于哪个学期：

| 状态 | semesterId | 系统里的表现 |
| --- | --- | --- |
| 本学期课程 | 当前学期的 id | 全校课程、听课计划、评价进度里都能看到 |
| 已归档课程 | 上一学期的 id | 日常界面看不到，但仍在库里，历史评价照样能点开 |
| 尚未归档的历史数据 | `NULL` | 按当前学期处理（兼容升级前的老数据） |

所以「把上一个学期的课程表拿开，存到另一个地方」= 给旧课程打上旧学期的标记，
**不需要**、也**不应该**去删表或备份成另一张表。

> ⚠️ 千万不要用 `DELETE FROM courses` 或 `TRUNCATE` 来换学期。
> 课程一旦删掉，去年所有评价记录里的课程名、教师、学院就全部变成空白。

---

## 二、操作步骤

### 第 0 步：先备份（必做）

```bash
bash scripts/server-backup.sh
```

备份包内含明文的 `.env`、数据库密码等，属于机密文件，不要放到共享盘。

### 第 1 步：升级代码并执行数据库迁移

```bash
git pull
pnpm install
pnpm db:push          # 等价于 drizzle-kit generate && drizzle-kit migrate
```

本次涉及两条迁移：

- `0008` 给 `courses` 增加 `semesterId`
- `0009` 把 `classId` 从 varchar(64) 放宽到 varchar(255)
  （MBA 课表存在多个班合上一节课的情况，班级名并列写在一起，实测最长 159 字符）

### 第 2 步：确认学期第一周的周一

这是**整个流程里最关键的一个参数**。

标准研究生课表里写的是「第几周」，而 MBA 课表只有具体日期（如 `2026-09-12`），
需要靠学期起始日换算成周次。**起始日差一周，整张 MBA 课表的周次就整体错一周**，
督导会按错误的周次去听课。所以导入工具不做任何猜测，必须显式传入。

2026-2027 学年第一学期的取值是 **2026-09-07（周一）**，共 **18 周**。依据：

- MBA 课表最早一次上课 2026-09-12、最后一次 2027-01-10；
- 以 2026-09-07 起算，87 个上课日正好落在第 1~18 周；
- 换成 2026-08-31 会得到第 2~19 周（没有第 1 周），换成 2026-09-14 会得到第 0 周 —— 都不成立。

以后换学期时，用同样的方法核对一遍即可。

### 第 3 步：试运行（不写库）

```bash
npx tsx scripts/import-courses.ts \
  "2026-2027学年第一学期研究生排课信息表.xls" \
  "MBA2026-2027学年第一学期课表.xls" \
  --semester 2026-2027/第一学期 \
  --start-date 2026-09-07 \
  --weeks 18
```

工具默认就是试运行，**不加 `--apply` 绝不写库**。请逐项核对输出：

- 两个文件各自被识别成什么格式、原始多少行、解析出多少门课；
- 学院分布（确认 `工商管理学院` 与 `MBA学院` 已经分开）；
- 「合并重复记录」这一段 —— 真实课表里有几十组「学院+课程+教师+星期+节次+教室」
  完全相同、只有周次不同的记录，工具会把周次取并集合并，并告诉你多保住了多少个周次；
- 「旧课表处理」—— 确认是「归档，不删除」；
- 「本学期课表变更」—— 新增/更新/删除各多少门。

### 第 4 步：正式导入

```bash
# 同样的命令加上 --apply；确认课表无误后再加 --activate 切换当前学期
npx tsx scripts/import-courses.ts <同上> --apply
```

写库全过程在一个事务里，中途任何一步失败都会整体回滚，不会留下半套数据。

### 第 5 步：切换当前学期

导入和「设为当前学期」是分开的两步，方便先把课表导进去核对、确认无误再切换。

- 界面操作：统计仪表盘 → 学期配置 → 在目标学期上点「设为当前」；
- 或重跑第 4 步的命令并加上 `--activate`。

切换后：全校课程、听课计划、评价进度都只显示新学期；旧学期的评价记录仍可正常查看。

### 第 6 步：导入/核对人员名单

```bash
npx tsx scripts/import-users.ts 角色信息表.xlsx            # 试运行
npx tsx scripts/import-users.ts 角色信息表.xlsx --apply    # 正式导入
```

导入后请在「用户管理」里确认督导范围：系统的安全默认是**校级**，
真正的院级督导需要逐个标成「院级督导」并填写所属学院。

## 三、两种课表格式

导入工具按**表头名**识别格式并取值（不按列序号），学校调整列顺序也不会错位。

### 格式一：研究生排课信息表

一行 = 一个开课记录，周次写在「自定义周次」列里。

```
学年 学期 开课院系 课程名称 课程性质 教室名称 班级编号 主讲教师 校区名称
星期几 单双周 节次 自定义周次 学生专业 选中人数 备注
```

### 格式二：MBA 课表

一行 = **一次上课**，需要按日期换算周次并归并成课程。

```
学期 班级 课程名称 课程性质 考试 授课教师 教室 日期 星期 上课时间 下课时间 课程班人数
```

处理方式：

- 「班级+课程+教师+星期+起止时间+教室」相同的多次上课归并成一门课，日期集合换算成周次；
- 节次用实际起止时间表示（如 `09:00-12:00`）；
- 合班的班级名（`2026MPM1班2026MPM2班2026MPM3班`）按年份切开，显示为顿号分隔；
- 「(考试)xxx」是考试场次，不是授课，不进课表；
- MBA 课表没有校区列和学生专业列，导入后这两项为空，如需要请在课程管理里补充。

## 四、学院口径（工商管理学院 / MBA 学院拆分）

自 2026-2027 学年起，两院在系统里是**两个独立学院**：

| 来源 | 系统里的学院 |
| --- | --- |
| 研究生排课信息表中「工商管理学院（MBA学院）」的课程 | `工商管理学院` |
| MBA 课表的全部课程 | `MBA学院` |

依据：合写名下的 96 条记录全部是学术学位课程（企业管理、技术经济及管理、应用心理、
会计学等），MBA/MPM 等专业学位课程在单独的 MBA 课表里。

拆分后，MBA 学院的督导只能看到 MBA 课表导入的课程，工商管理学院的督导也看不到
MBA 的课，互不越界。学院名称的统一口径见 `shared/colleges.ts`。

## 五、重复导入与出错处理

- **重复导入同一学期**：按「学院+课程+教师+星期+节次+教室」UPSERT，课程 id 保持不变，
  已有的评价和听课计划不会失去关联。可以放心重跑。
- **课表改了再导一次**：本学期内新课表已不存在的课程会被删除，
  但**有评价或听课计划关联的一律保留**，输出里会报告保留了几门。
- **其他学期（已归档）的课程任何情况下都不会被动。**
- **字段超长**：导入前会自查各列长度，超出就中止并指出是哪门课的哪个字段，
  不会写到一半才被数据库拒绝。
- **网页上传课表**（上传课程数据页）与本命令行工具共用同一套解析与写入逻辑，
  行为一致；但网页上传只作用于当前学期，换学期请用命令行工具。

## 六、验证清单

导入后请依次确认：

- [ ] 全校课程条数 = 本学期课程数（当前为 1832 门）
- [ ] 学院筛选里 `工商管理学院` 与 `MBA学院` 分别存在
- [ ] 随手点开一条去年的评价，课程名/教师/学院仍然显示正常（没有变空白）
- [ ] 统计仪表盘「学期配置」里两个学期都在，当前学期标记正确
- [ ] 某个 MBA 院级督导登录后，只看得到 MBA 学院的课
- [ ] 统计仪表盘三张学院图表的学院数量一致
