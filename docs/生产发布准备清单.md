## 第一关：恢复连接，只读诊断

- [ ] SSH 可用，并确认操作的是本次生产服务器，不是其他历史服务器。
- [ ] 检查内存、磁盘、负载和应用健康；不打印环境变量、会话密钥或连接串。
- [ ] 如需结束候选检查进程，先核实准确 PID、命令和工作目录；不得按所有 Node 进程批量终止。
- [ ] 通过 PM2 获取应用标识和实际工作目录，但不输出完整环境配置。
- [ ] 记录实际 HEAD、远端仓库、工作区差异和当前运行产物。

若工作区有不明改动、目标目录不符或诊断报错，停止并报告；不覆盖、不强制重置、不清理未知文件。

## 第二关：版本、备份与产物

- [ ] 记录目标 GitHub 完整 SHA，并确认生产旧版本到目标的提交关系。
- [ ] 单独核对依赖文件及数据库定义差异。本批学期功能不需要执行迁移或重新导入课表；如发现额外变化，重新审查发布范围。
- [ ] 发布前备份满足恢复要求，保存校验值和访问受限的位置；秘密配置及备份不得提交 GitHub。
- [ ] 保存旧构建产物和准确回滚版本；只保存 Git SHA 不足以恢复被覆盖的构建文件。
- [ ] 在本地或独立构建环境生成产物，记录源 SHA 和产物 SHA256；避免在小内存生产机重复运行类型检查和全量测试。
- [ ] 传输构建产物不代替源代码同步：服务器检出与产物必须能追溯到同一批准版本。
- [ ] 复用已有候选产物前核实其源码一致性和校验值，不因目录存在就直接启用。

本批不运行数据库集成测试到生产库，不运行迁移、课表重导或数据清理。若 GitHub 拉取失败，不自行采用压缩包覆盖源码；遵循已约定的有限重试方式，仍失败则报告。

## 第三关：上线前验证

- [ ] 候选只读核对新旧学期课程、评价及关联完整性。
- [ ] 以执行当时的只读统计为准。旧报告中的 80 条已提交评价只是历史快照，若有真实新增，不应强行回退到旧数字。
- [ ] 确认所有写入与角色越权测试已在隔离环境完成，不生成虚构生产评价。
- [ ] 确认维护窗口、执行人员和回滚触发条件。

## 第四关：正式启用与验收

- [ ] 按批准方式同步源代码及产物，重启指定应用，不重启不相关服务。
- [ ] 检查进程稳定、端口响应和外部页面可达；单个 HTTP 200 不代表业务验收通过。
- [ ] 检查应用日志；展示前移除密钥、连接串及个人数据，保留完整非敏感错误上下文。
- [ ] 硬刷新浏览器，确认加载新产物；必要时考虑旧页面仍引用旧静态资源的兼容问题。
- [ ] 核对上一学期与当前学期的列表、详情、统计和导出。
- [ ] 核对三图学院集合、实际评分口径和无数据提示。
- [ ] 用真实授权账号验证能查看本人记录；其他角色使用批准的测试账号，不伪造身份或令牌。
- [ ] 检查手机评分表与黑白打印无回归。

未拿到对应账号时记录“未验证”，不能以管理员测试代替督导、秘书验收。

## 第五关：回滚与交付

出现数据关联错误、越权、主流程无法使用或应用不稳定时，停止发布并按已验证路径恢复旧代码和构建产物。先核对上线期间真实新写入是否兼容；不要直接恢复旧数据库覆盖新评价。

交付记录必须包含：

- 完整源 SHA、构建 SHA256、上线时间、实际运行版本。
- 备份标识及校验结果（不含密钥），回滚产物位置。
- 验收项的通过/失败/未验证状态及证据。
- 未完成事项、责任方与下一步；不能只写“部署成功”。
