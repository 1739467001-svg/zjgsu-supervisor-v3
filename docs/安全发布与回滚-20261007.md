## 固定版本与目录

目标Linux服务器使用 `/srv/zjgsu-supervisor`：`releases/<完整40位提交号>` 保存不可覆盖的代码、构建和生产依赖；`current` 指向运行版本，`previous` 保存上一版本；`shared/runtime.env` 保存运行配置。原系统目录、原构建及原数据库备份另行保留。版本以 `release.json` 和 `release.env` 为准，禁止用有改动工作区冒充提交版本。

准备命令不会切换或重启服务：

```bash
node scripts/release-update.mjs prepare --repo /srv/zjgsu-source \
  --root /srv/zjgsu-supervisor --revision 完整40位发布提交号
```

准备过程从Git提交归档，冻结锁文件安装依赖，类型检查、构建，再仅安装生产依赖。任一步失败保留准备目录，旧服务不变。构建不读取生产配置；完成后记录文件SHA256、Node版本和平台。上线应在目标Linux环境构建，不能复制macOS的node_modules。

脚本要求Node22.12或以上；目标服务器固定受支持的Node主版本，pnpm使用package.json声明版本。Vite本身要求Node20.19+/22.12+，见[官方文档](https://vite.dev/guide/)。本轮真实构建使用本机Node25，目标Linux的Node及包管理器兼容仍需新服务器验证。

2. 安装核实后的运行环境，创建专用服务用户和仅本机监听的数据库，开放80/443，3000与3306不对公网开放。

5. 构建固定版本。首次启动不能调用activate冒充已有current：核实清单后建立current链接，在受限配置下启动服务，检查数据库健康、登录、改密门禁及角色边界，再启用外部代理。

## HTTPS、会话与代理

使用[nginx模板](../deploy/nginx.conf.example)替换学校确认域名和真实证书路径；先检查配置再加载。HTTP跳转HTTPS，证书续期须验证。单台本机代理才设置 `TRUST_PROXY=loopback`，外部客户端不得直连应用端口。代理覆盖转发头，服务端Cookie只按已核实的代理协议设置Secure。不要把任意来源标为可信代理，见[Express官方说明](https://expressjs.com/en/guide/behind-proxies/)。

运行配置文件限制为服务用户可读，JWT_SECRET至少32字符；用安全渠道配置，命令输出、Git和截图均不得出现秘密。上传大小限制21MB，应用仍执行原校验。nginx对工号登录（含批量请求路径）按来源限流，应用按账号及IP追加限制；多实例必须统一代理限流策略。规则来源见[nginx官方文档](https://nginx.org/en/docs/http/ngx_http_limit_req_module.html)。模板已静态审查，真实nginx加载、TLS及公网429尚未测。

## 回滚

```bash
node scripts/release-update.mjs rollback --root /srv/zjgsu-supervisor \
  --service zjgsu-supervisor.service --port 3000
```

代码回滚只恢复旧代码、构建和运行版本，不覆盖数据库。若本次发布单独批准过结构变更或数据迁移，须使用该步骤自己的兼容/恢复方案，不能靠代码回滚撤销。旧版健康失败不继续来回切换；保留现场、日志和所有备份，由负责人处置。
